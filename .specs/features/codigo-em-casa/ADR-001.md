# ADR-001 — Sair da Base44

**Status:** ✅ aprovado — as 4 decisões fechadas em 04/09/2026
**Data:** 04/09/2026
**Decisão de origem:** `GOAL.md` §5, saída **B**

---

## 1. A superfície é pequena — e isso muda o tamanho da obra

Antes de medir, "sair da Base44" parecia grande porque o SDK aparece em 21
chamadas espalhadas por 12 arquivos. **A medição desmontou isso.**

O achado que decide: **`base44/functions` não existe.** Nenhuma função de
backend foi escrita neste app. Tudo o que o servidor da Base44 faz aqui é
genérico, e cabe em quatro famílias:

| família | chamadas | o que é |
|---|---|---|
| **Entidades** (CRUD) | 11 | `list`, `filter`, `create`, `update`, `delete` sobre 7 tabelas |
| **Autenticação** | 8 | `me`, `logout`, `redirectToLogin`, `isAuthenticated`, `updateMe` |
| **IA** | 5 | `integrations.Core.InvokeLLM` |
| **Telemetria** | 1 | `appLogs.logUserInApp` — descartável |

Não há regra de negócio no servidor deles. **Toda a lógica do produto já está
no frontend, que é nosso.** O que se troca é encanamento, não domínio.

### O detalhe do CRUD

Só 5 verbos, e nenhum exótico:

```
Child            list create update delete
Activity         list create update
InsightRating    list create
CommunityPost    list create update
CommunityComment filter create
ChatMessage      (nenhuma — entidade órfã, GOAL §4.2)
User             me updateMe
```

Isto é uma API REST de 7 recursos. Pelas regras do ecossistema
(`apis.md`, `code-standart.md` §2): um `apps/api-pai-presente` em Bun com
`Bun.serve`, Postgres + Drizzle, Zod na fronteira.

### O detalhe da IA

5 chamadas, **4 delas pedindo JSON estruturado** (`response_json_schema`).
Exemplo real, de `Juntinhos.jsx`: prompt em texto + schema pedindo
`{ suggestions: [{ title, description, category, child_name }] }`.

Qualquer provedor moderno faz isso (structured output / tool use). Não é
amarração. Mas há uma mudança **obrigatória** de arquitetura: hoje o
`InvokeLLM` é chamado **do navegador**, porque a chave do provedor é da Base44.
No nosso backend a chave é nossa, e **chave de LLM nunca vai para o bundle**
(`security.md` §4). A IA vira endpoint do servidor.

## 2. Três defeitos de segurança que vêm de brinde

Não são defeitos do app — são do desenho da Base44. Mas a migração é o momento
em que deixam de ser herdados e passam a ser escolha nossa.

### 2.1 O token viaja na URL e mora no `localStorage`

`src/lib/app-params.js` lê `?access_token=` da query string e grava em
`localStorage` sob `base44_access_token`.

Isso viola duas regras nossas ao mesmo tempo:
- `apis.md`: token em `Authorization`, **nunca em query param** (a URL vai para
  histórico do navegador, log de servidor e `Referer`)
- `security.md` §8: **nunca `localStorage` para token** — qualquer XSS o lê

**No backend novo:** cookie `HttpOnly` + `Secure` + `SameSite`, access token
curto (≤15 min) e refresh rotativo (`security.md` §2). O `app-params.js` inteiro
deixa de existir.

### 2.2 Dado sensível vai para o provedor de IA

Os prompts de `Home.jsx`, `Comunidade.jsx` e `Chat.jsx` mandam, em texto:

```
Orientação religiosa: ${user.religious_orientation}
Orientação política: ${user.political_orientation}
```

Ou seja: dado pessoal **sensível** (LGPD art. 5º, II) atravessa para um
subprocessador terceiro a cada tela carregada. Isto agrava o `GOAL.md` §4.3 —
lá o problema era coletar; aqui é **transferir**.

Não dá para resolver isto só no backend: depende de `TL.1` (o que fazer com os
três campos). Mas o backend novo é onde a decisão passa a ser aplicável.

### 2.3 A conversa do chat é conteúdo pessoal

`Chat.jsx` monta prompts com nome e idade dos filhos. Quando o chat passar a
persistir (§4.2), isso vira dado guardado. **Nunca vai para log**
(`security.md` §1), e o payload de fila carrega referência, não conteúdo (§6).

## 3. O frontend NÃO se reescreve agora

Tentação óbvia: o código ejetado não segue nossas regras de frontend —
é `.jsx` sem TypeScript, texto em português cravado na tag (sem i18n, `web.md`
§6), cor e espaçamento hardcoded (§8), nomes de arquivo fora do padrão (§2).

**E mesmo assim: não se reescreve junto.** A regra é nossa, `web.md` §14:
*"Não migrar tela que funciona. Migração é trabalho com risco e sem ganho
visível ao usuário."*

Trocar o backend já é uma mudança grande com risco real. Empilhar uma reescrita
de 71 arquivos `.jsx` em cima disso produz um estado em que, quando algo
quebrar, ninguém sabe qual das duas mudanças quebrou.

**Ordem:** primeiro o backend novo servindo o frontend atual, com o app
funcionando igual. Depois, tela a tela, quando houver motivo.

O que muda no frontend nesta fase é só o **encanamento**:
- `src/api/base44Client.js` → cliente HTTP nosso
- `src/lib/AuthContext.jsx` → nosso fluxo de auth (some o import de
  `@base44/sdk/dist/utils/axios-client`, que é interno do SDK deles)
- `src/lib/app-params.js` → deletado (§2.1)
- `vite.config.js` → sai o `@base44/vite-plugin`
- `src/lib/NavigationTracker.jsx` → sai o `appLogs` ou vira telemetria nossa

Sete arquivos de encanamento. As 8 páginas ficam como estão, trocando só a
origem do import.

## 4. Arquitetura proposta

Pelas regras do ecossistema (`code-standart.md` §2):

```
pai-presente/
  apps/
    api-pai-presente/      Bun.serve · Postgres · Drizzle · Zod
    frontend-pai-presente/ o código atual, movido
  packages/
  envs/                    env.dev, env.dev.local, env.test, env.test.e2e
  docker-compose.yml       Postgres local
  Makefile                 PROJECT_NAME propagado
```

**Banco:** as 7 entidades viram schema Drizzle. Sem ENUM nativo — VARCHAR
(`code-standart.md` §8). PK em UUID. Migrations versionadas.

**API:** `/v1/children`, `/v1/activities`, `/v1/insight-ratings`,
`/v1/community/posts`, `/v1/community/comments`, `/v1/chat/messages`, `/v1/me`.
Envelope `{ data }`, erro `{ error: { code, message } }`.

**IA:** `POST /v1/insights`, `/v1/activity-suggestions`, `/v1/report`,
`/v1/chat` — servidor chama o provedor, cliente nunca vê a chave.

## 5. O problema que ainda não tem solução: os dados

O app original (`69693b3d…`) tem usuários reais e os dados deles. **O eject não
trouxe nenhum registro** (`GOAL.md` §2), e ainda não encontrei caminho de
exportação.

Três saídas possíveis, nenhuma verificada ainda:
1. exportação pelo painel da Base44 (existe? não sei)
2. ler tudo pela API do app original com um token válido e gravar em arquivo
3. começar do zero e pedir recadastro

Isto vira `TB.0` no `tasks.md` e é **anterior** a qualquer código, porque a
resposta muda o esquema do banco novo (migrar dado exige campo de origem e
idempotência; começar do zero, não).

⚠️ Qualquer exportação de dado real de usuário é operação com dado pessoal:
arquivo criptografado, fora de repositório, e nada em log.

## 6. As decisões — 3 fechadas, 1 aberta

### ✅ D2 — começar do zero (04/09/2026)
O banco novo nasce vazio; quem usa hoje se recadastra.

Consequências, e a segunda é a que mais importa:
- **`TB.0` cai.** Não é preciso descobrir se a Base44 exporta dado. Some junto
  o risco de manusear dado pessoal real fora do ambiente dele.
- **O passivo de §4.3 zera.** Os cadastros com orientação sexual, religiosa e
  política ficam no app antigo e não atravessam. Se `TL.1` decidir remover os
  campos, o banco novo simplesmente nunca os teve.
- O banco novo não precisa de campo de origem nem de rota de importação.

⚠️ Isto **não** apaga o dado que já existe no app original. Desligar ou expurgar
aquele app continua sendo decisão pendente (§7).

### ✅ D4 — provedor de IA trocável por variável de ambiente (04/09/2026)
Nenhum provedor escolhido agora. O backend expõe **uma interface** e escolhe o
adaptador por `LLM_PROVIDER`.

Isto já é o que as regras pedem — `code-standart.md` §6 (dependência por
interface, sem `new` acoplado) e `nodejs.md` (env por schema validado no boot):

```
LlmProvider (interface)
  generateStructured({ prompt, schema })  -> os 4 usos com response_json_schema
  generateText({ prompt })                -> o chat

adapters/anthropic.provider.ts
adapters/openai.provider.ts

LLM_PROVIDER=anthropic|openai   (validado por Zod no boot; sem default silencioso)
LLM_API_KEY=...                 (só no servidor, nunca no bundle)
```

A chave **nunca** tem prefixo `VITE_` — o Vite inlina isso no bundle
(`security.md` §4).

### ✅ D5 — Fly.io ou Railway (04/09/2026)
Postgres gerenciado com backup incluso, e Bun sobe sem configuração de máquina.
A escolha final entre os dois fica para `TB.10`; os dois atendem, e nada no
código depende de qual for.

### ✅ D3 — login por Google e Apple (04/09/2026)
Sem senha própria. O que isso apaga do trabalho, e é a razão da escolha:
guardar hash, tela e e-mail de "esqueci minha senha", bloqueio por tentativa e
política de senha — cada um deles é código nosso e superfície de ataque nossa.

O que fica sob nossa responsabilidade mesmo assim:
- **sessão**: cookie `HttpOnly`+`Secure`+`SameSite`, access ≤15 min, refresh
  rotativo com invalidação do anterior (`security.md` §2)
- **conta**: o `sub` do provedor vira nosso `userId`; o e-mail é atributo, não
  chave — a mesma pessoa pode chegar pelo Google e pela Apple
- **Apple esconde o e-mail** (relay privado). O cadastro não pode depender de
  e-mail real, e ligar contas por e-mail quebraria justamente aí
- **exclusão de conta** é obrigatória pela Apple, e é direito do titular pela
  LGPD (art. 18) — vira rota, não pedido por suporte

## 6.1 PWA — sim, e hoje ele está quebrado

Pergunta do usuário: *"consegue fazer pwa"*. **Sim** — e é obrigatório pelas
nossas regras (`web.md` §10), não opcional.

Mas a medição achou uma coisa: **o app se declara PWA e não é.**

`index.html` tem `<link rel="manifest" href="/manifest.json" />` — e **não
existe pasta `public/` nem arquivo `manifest.json`**. O navegador pede, recebe
404, e nenhum celular oferece instalar.

Outros três defeitos no mesmo arquivo de 12 linhas:

| linha | está | deveria |
|---|---|---|
| `<title>` | `Base44 APP` | `Pai Presente` |
| `<link rel="icon">` | `https://base44.com/logo_v2.svg` | ícone nosso, local |
| `<html lang>` | `en` | `pt-BR` |

Ou seja: o app hoje mostra o nome e o logotipo da Base44 na aba do navegador.

**O que entra:** `vite-plugin-pwa` com manifest (nome, short_name, ícones 192 e
512 PNG, `display: standalone`, theme_color), service worker — cache-first para
asset, network-first para API —, `offline.html` com a marca, e as meta tags de
theme-color e apple-touch-icon.

E o aviso de ambiente do `web.md` §12: fora de produção, o ícone da aba ganha a
plaquinha 🚧 e aparece a faixa de ambiente.

Isto vira `TB.10`, e **depende de haver um ícone do produto** — que hoje não
existe. É a única dependência de arte deste plano.
